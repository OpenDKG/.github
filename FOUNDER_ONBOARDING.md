# OpenDKG — three equal cofounders: onboarding and acceptance

**Status: proposal.** This document describes the team's intended founding arrangements. It does not bind someone who has not personally agreed, create a company, transfer intellectual property, or distribute legal liability.

## Founding relationship

OpenDKG is intended as a project **cofounded from the outset by three equal individuals**:

- `@a-51-50` — one of the three equal cofounders; presently the **technical GitHub Organization Owner** because this account created the organization.
- `@dreddster` — one of the original equal cofounders; personal acceptance of the pinned policy is still required.
- `@brxtrac` — one of the original equal cofounders; personal acceptance of the pinned policy is still required.

These are **three equal founding seats**. Who created the GitHub account first does not confer additional votes, project copyright, founders' ownership rights, or permanent control. The other original cofounders are not ordinary later-stage applicants merely because their GitHub invitations have not yet been sent. However, **do not claim that anyone is contractually bound until they personally accept** the relevant agreement.

**Exact proposed Governance and Contributor Agreement revision for acceptance:** `d56279b4f3c25dd8f9e68699d61be23a0c7a6b07`. The underlying documents remain v1.0 proposals and were clarified before any of the three original cofounders had accepted. An outdated revision is not adequate consent to this clarified version.

## How each of the three accepts (including the initial technical Owner)

1. Read [Contributor Agreement v1.0 at the pinned revision](https://github.com/OpenDKG/.github/blob/d56279b4f3c25dd8f9e68699d61be23a0c7a6b07/CONTRIBUTOR_AGREEMENT.md) and [Governance v1.0 at the same revision](https://github.com/OpenDKG/.github/blob/d56279b4f3c25dd8f9e68699d61be23a0c7a6b07/GOVERNANCE.md).
2. Each of the original three individually opens [founding acceptance Issue #3](https://github.com/OpenDKG/.github/issues/3) **from their own GitHub account**. You can comment **without being an organization member** because the repository is public.
3. Each personally posts the declaration provided in Issue #3 after actually reading the documents. No owner, agent or bot may post acceptance for another person. A GitHub comment is evidence of an attributable public action, not verified civil identity or a qualified electronic signature.
4. The current GitHub Owner checks that exactly three **different original-cofounder accounts** submitted explicit acceptance of the **same pinned revision**. Record three comment permalinks in the issue and only then mark the full founding council as formed. If the text changes substantially, collect agreement to the final version again.
5. For each original cofounder who has accepted, `@a-51-50` may invite their account to the organization; there is **no need to wait until all three are already GitHub members**. Joining as a **Member** is acceptable until the full founder roster is agreed and organizational permissions are reviewed.
6. After unanimous adoption, assign GitHub privileges by an explicit, documented founders' decision. If all three are meant to have equal technical control, **Organization Owner** for all three is more equivalent than giving two people only **Repository Admin**. But GitHub Owners have powerful unilateral platform capabilities, so all three should understand this risk and use MFA, separate recovery methods, least privilege and review controls. This process **does not automatically grant any account Owner or Admin**.
7. Ordinary later contributors apply via [the membership form](https://github.com/OpenDKG/.github/issues/new?template=membership-agreement.yml) or submit PRs as external contributors. They have **no cofounder status**, no governance vote and no automatic admin permissions.

## Automatic verification once the three usernames are known

The [founder adoption automation](FOUNDER_ADOPTION_AUTOMATION.md) will verify and close Issue #3 when all three **specific** original GitHub accounts have personally accepted the **exact same policy revision**. It records a verification receipt. The three account handles are recorded in [the founder roster](.github/founder-roster.json); it cannot close Issue #3 until all three individuals have posted personal valid acceptances. The first account's existing valid acceptance is preserved; do not require `@a-51-50` to sign again without a material policy change.

Issue comments can still be edited or deleted. On such a change after automatic closure, the bot will reopen Issue #3 if any previously verified acceptance is no longer currently present. This is an integrity check, not an immutable legal e-signature. No GitHub privileges are granted automatically.

## Accountability and limits

No statement in GitHub governance makes the three persons automatically jointly liable for each other's activities, automatically shields `@a-51-50` from liability, or turns a GitHub organization into a limited-liability company. This must be addressed separately under the relevant jurisdictions and in actual contracts, if any. Do not represent an unregistered collaboration as an LLC.

These documents are for organization operations and permission/provenance evidence. For legally enforceable founder duties and financial or IP allocation across jurisdictions, have appropriate counsel review the arrangement. Never post passports, addresses, private contact information, cryptographic secrets or identity documents publicly.
